# Project Overview
`active_learning` is a Python package for orchestrating atomistic active-learning loops end to end:
run simulation tasks, validate outputs, label data with SP references, split datasets, and retrain
MLIP engines. It favors composable abstractions (`Task`, `CheckerGetter`, `JourneyScheduler`,
`MLIPTrainer`) so domain workflows can be implemented quickly without hard-coding model internals.

## Repository Structure
- `src/scm/active_learning/`: Core package code (loop engine, tasks, journeys, checks, trainers,
  callbacks).
- `tests/`: Pytest suite, including notebook execution via `testbook`.
- `tutorials/`: Jupyter tutorials; currently two non-empty examples and two zero-byte placeholders.
- `scripts/`: Utility scripts (for example README coverage line updates).
- `images/`: Diagrams used by docs (`active_learning.png`, `active_learning_workflow.png`).
- `doc/`: Documentation staging folder (currently empty).
- `old/`: Legacy/experimental code; avoid using it as implementation reference unless requested.
- the rest of the folders are run artifacts; treat as output data, not source code.

  variants.

## Optional Dependencies Policy
Source of truth: `pyproject.toml`.

Current groups:
- Required runtime dependencies (`project.dependencies`): `loguru`, `moliterate`, `plams`,
  `pydantic`, `tabulate`, `typing-extensions`.
- Optional extras (`project.optional-dependencies`):
  - `tutorial`: `jupyterlab`.
- Dev-only tools (`dependency-groups.dev`): `coverage`, `pytest`, `ruff`, `testbook`
  (testing/tooling, not runtime API requirements).

Implementation rules for interfaces:
- Treat optional dependencies as truly optional at runtime: do not import them at package import time
  unless they are in `project.dependencies`.
- Prefer lazy/local imports for optional integrations and raise a clear error with install guidance
  when missing (for example: `pip install -e .[tutorial]`).
- When adding new serialized path-bearing fields, register their key patterns in
  `src/scm/active_learning/logging/state_paths.py`. `save_folder` is already covered, but output
  file fields such as `trajectory_path` are not automatic.
- Hide optional dependency types from hard runtime contracts when possible:
  use `typing.TYPE_CHECKING`, `Protocol`, or internal adapters so public interfaces can still load
  without optional packages installed.
- If adding a new optional integration, declare it under `project.optional-dependencies` and keep
  fallback behavior explicit.

Testing rules for optional dependencies:
- Base tests should remain runnable without extras (`just test-base`).
- Tests that require optional dependencies must be explicitly guarded with
  `pytest.importorskip(...)` or `@pytest.mark.skipif(...)` and include a short reason.
- Prefer skip reasons that tell maintainers which extra/group to install.
- Add at least one negative-path test (or assertion) for graceful behavior when an optional dependency
  is unavailable.

## Architecture Notes
```text
ActiveLearningLoop
  |
  +--> JourneyScheduler.run_current_batch(engine)
  |       -> Task(s) -> CheckerGetter(s) -> CollectionCheckGetResults
  |
  +--> IterationState.label(pre_filter, SPLabeller, labeller_engine, post_filter)
  |       -> SPLabellingResults
  |
  +--> IterationState.accuracy(...)
  |       -> SPChecker metrics vs start engine
  |
  +--> JourneyScheduler.advance(validity, accuracy)
  |       -> JourneyAdvanceResult (can skip train / converge)
  |
  +--> DataAndSplittingStrategy.split_and_add(...)
  |       -> train/validation tagging in dataset store
  |
  +--> MLIPTrainer.train|finetune(...)
          -> next engine for next iteration
```

Main component groups:
- `loop/`: Orchestration (`ActiveLearningLoop`, `IterationState`, stop/phase handling).
- `journey_scheduler/`: Defines which tasks/checks run and convergence/advance logic.
- `tasks/`: Executable work units (AMS tasks, conformers, SP labelling).
- `checker_getters/`: Validation and frame/data extraction after task execution.
- `mlip_trainer/`: Training/finetuning interfaces and dataset splitting strategy.
- `engines/`: Engine abstractions (`AMSEngine`, `ParAMSEngine`) and parallelization settings.
- `callbacks/`: Side effects around loop phases (state logging, folder management, skip behavior).
- `cli/`: Command-line apps under `src/scm/active_learning/cli/`; every new CLI app should get its own file there.

## Agent Guardrails
- Never modify generated/runtime artifacts unless explicitly asked:
  `ALruns/`, `htmlcov/`, `.amspy/`, `.coverage`, `coverage.json`, `pytest.log`, `plams_workdir*`.
- Never rewrite large legacy folders (`old/`) unless the task explicitly targets them.
- Ask before changing dependency declarations (`pyproject.toml`) or running long AMS-heavy suites.
- Prefer narrow validation first: run relevant tests and `just ruff` before full `just test`.
- Keep diffs scoped to the requested feature/fix; avoid opportunistic refactors.
- For user-facing CLI commands, prefer helpful failures: print subcommand help before exiting on
  missing required arguments or validation errors, and avoid exposing raw Pydantic tracebacks.
- Required review focus:
  changes in `src/scm/active_learning/loop/` and `src/scm/active_learning/journey_scheduler/`
  should receive explicit maintainer review because they alter AL loop semantics.
- Rate-limit expensive loops:
  run `just test-amspy` at most once per iteration unless the user asks for repeated runs.

## Extensibility Hooks
- New tasks: subclass `Task` in `src/scm/active_learning/tasks/core.py`, then wire into
  `ConcreteTask` union in `src/scm/active_learning/tasks/__init__.py`.
- New checker/getter combos: implement `CheckerGetter` (or checker/getter primitives) and register
  in `ConcreteCheckerGetter` in `src/scm/active_learning/checker_getters/__init__.py`.
- New journeys: subclass `JourneyScheduler` in `journey_scheduler/core.py` and add to
  `ConcreteJourneyScheduler`.
- `JourneyScheduler.run_current_batch()` defines part of the scheduler contract. Prefer reusing the
  base implementation whenever possible. If a journey overrides it, preserve the same interaction
  pattern unless there is a documented reason not to: call `register_attempt()`, execute via
  `task_parallelization.run_tasks(...)`, keep task/result ordering aligned with
  `_current_batch_check_getters()`, and apply checker/getter processing before returning
  `CollectionCheckGetResults`.
- New trainers/engines: implement `MLIPTrainer` / `Engine` contracts and register discriminated
  unions where needed.
- New CLI apps: add a dedicated module in `src/scm/active_learning/cli/` and keep top-level command
  routing thin.
- Loop side effects: add callbacks via `ALCallback` implementations in `callbacks/`.
- Environment hooks: `.env` is consumed by AMS test recipes (`AMSBASHRCPATH`, `SCM_PYTHONDIR`).
